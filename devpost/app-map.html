LETTER ASSISTANT / SOURCE REFERENCE / 2026-10-26

从一封信，到一个日历事件

iPhone 原生应用：拍照或导入英文信件，在本机检查可读性，用所选的中文或英文解释内容，再核对日期、提醒和备注并保存到日历。此地图是简短静态回顾的参考路线，不代表完成了互动练习。

01 拍照 / 导入

相机、照片或 PDF → 本机检查 → 临时页面列表。

CaptureModel.accept / acceptDocument / validate
02 AI 分析

有序页面 → Mac relay → 操作者配置的 AI → 校验结果 → 四段解释。

CaptureModel.interpret → LetterAPI.interpret → /interpret
03 核对 / 添加

提取的行动 → 日历提案 → 用户核对 → EventKit → iPhone 日历。

CalendarProposal.make → addToCalendar → SystemCalendarWriter.save

照片与解释只保留在当前会话；添加成功的事件独立保留在系统日历。AI 密钥在 Mac 上。图片在点击分析后经 relay 发送给配置的外部 AI 服务。

三个代码站点

  1. CaptureModel.swift：搜索 accept、validate、interpret。照片准备、页面顺序和可读性决定何时可分析；失败保留页面以便重试。
  2. LetterAPI.swift：搜索 func interpret 和 send。将图片、页面 ID 和语言提交到 relay。interpretation-relay.ts 负责令牌、限制和调用服务；validation.ts 检查 AI 返回格式与引用，不能证明事实全部正确。
  3. CalendarReviewView.swift：搜索 addToCalendar、CalendarEventRequest、SystemCalendarWriter。界面把核对后的字段组装成请求，获得仅写入授权后存入默认日历。CalendarProposal.make 将来源行动转换为初始提案。

想改这里，从哪里开始

  • 拍照入口、页面与解释排版：CaptureView.swift。
  • 模糊和可读性判断：PageQualityService.swift；相机连接：CameraService.swift。
  • 解释规则、输出约束：prompts.ts 与 contracts.ts。
  • 日期和备注：CalendarProposal.make / notes；提醒选项：CalendarAlertChoice；最终日历写入：CalendarEventRequest.makeEvent。

下次可复用的做法

把“添加日历正常”拆成可观察的结果：事件日期、全天/定时设置、提醒和备注均应与核对界面一致。checklist.md → Hands-on Checkpoints 保存手机证据；LetterAssistantTests.swift 的 testCalendarAllDayEndUsesLocalDayAcrossDST 检查跨夏令时的全天结束日期。测试和手机观察互补；模拟输出无法证明任意真实信件的 AI 准确度。

重新运行与验证

按 README 建立忽略的本地配置，使用自己的 AI key 与 relay token，运行 deno task relay。在 Xcode 打开 ios/LetterAssistant.xcodeproj，选择 LetterAssistant-Test、自己的签名团队和 iPhone。手机与 Mac 使用同一可信局域网。

后端验证：deno task check、deno task test。新操作者的签名、真实提供商与通知到达仍需独立验证。
